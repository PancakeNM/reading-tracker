# Research: Доменное ядро учёта чтения

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-10-11 | **Revised**: 2026-10-12

Ограничение этапа (указание пользователя): без базы данных, без HTTP, без внешних библиотек — только стандартная библиотека Go и пакет `testing`.

## R1. Версия Go и тулчейн

- **Decision**: Go 1.22 или новее, в `go.mod` директива `go 1.22`. Проверки: `go build`, `go vet`, `gofmt`, `go test` — всё входит в стандартный тулчейн.
- **Rationale**: ни одна возможность новее 1.22 не нужна. Директива `go 1.22` позволяет собирать любым более свежим тулчейном.
- **Alternatives considered**: сторонние линтеры (golangci-lint) запрещены ограничением этапа.
- **Note**: на машине разработчика Go сейчас не установлен. Установка — предусловие в [quickstart.md](./quickstart.md).

## R2. Размещение модуля и пакета

- **Decision**: один модуль в корне репозитория `github.com/PancakeNM/reading-tracker`, доменное ядро — пакет `domain` в `internal/domain/`.
- **Rationale**: выбор пользователя. `internal/` не даёт импортировать ядро извне модуля, путь модуля совпадает с remote `origin`.
- **Alternatives considered**: модуль сервиса `services/reading/` или несколько модулей по сервисам — преждевременно фиксируют границы сервисов. Отклонение от принципа IV конституции обосновано в Complexity Tracking плана.

## R3. Отказ от `Reading`: куда переехало поведение

- **Decision**: сущности `Reading` нет. Прогресс записывается методами `ReadingLog`, статус и даты живут в `ShelfItem`, оценка проверяется в `Review`.
- **Rationale**: решение пользователя. `Reading` дублировал `ShelfItem` (пара «пользователь + книга», статус) и `ReadingLog` (прогресс). Два источника истины для статуса дают противоречия.
- **Alternatives considered**: оставить `Reading` рядом с `ShelfItem` — дублирование статуса; копировать статус в `ReadingLog` — то же дублирование.

## R4. Связь `ReadingLog` → `ShelfItem`

- **Decision**: методы прогресса принимают `*ShelfItem` и общий объём параметрами:
  `UpdateProgress(item *ShelfItem, page, totalPages int) error` и
  `UpdateAudioProgress(item *ShelfItem, seconds, totalSeconds int64) error`.
  `item == nil` означает «записи на полке нет»: проверяются только аргументы.
- **Rationale**: выбор пользователя. Метод остаётся у `ReadingLog`, статус живёт только в `ShelfItem`. Соблюдено `DESIGN.md` §5.4: запись о чтении не требует записи полки. Объём приходит параметром, потому что `ReadingLog` хранит только `BookID`, а не саму книгу.
- **Integrity check**: если `item` не `nil`, его `UserID` и `BookID` обязаны совпадать с записью о чтении, иначе `ErrShelfItemMismatch`. Без этой проверки прогресс одной книги мог бы завершить другую.
- **Alternatives considered**: отдельная функция `RecordProgress(item, log, …)` — чище, но метод перестаёт принадлежать `ReadingLog`.

## R5. Смысл `Pages` и `Seconds`

- **Decision**: позиция («дошёл до страницы N», «дослушал до секунды N»), а не прирост за подход.
- **Rationale**: выбор пользователя. Правила «не больше общего» и «равно общему → прочитано» работают по одной записи, без знания прошлых. Расхождение с формулировкой `DESIGN.md` §4.10 («сколько прочитано за один подход») записано в Assumptions спецификации.
- **Alternatives considered**: прирост — методу пришлось бы передавать сумму прошлых записей.

## R6. Подмена «текущего момента» (FR-022)

- **Decision**: неэкспортируемое поле `now func() time.Time` в `ShelfItem`. Приватный помощник возвращает `time.Now()`, если поле `nil`. Методы `ReadingLog` берут время у переданного `item`, потому что текущий момент нужен им только для дат полки. Тесты в том же пакете (`package domain`) задают `now` фиксированной функцией.
- **Rationale**: выбор пользователя (вариант «поле-функция»). Часы локальны для объекта, тесты изолированы и идут параллельно (`t.Parallel()`), глобального состояния нет. Время нужно только тем, кто ставит или проверяет даты, а это `ShelfItem`.
- **Alternatives considered**: переменная пакета — глобальное состояние, нельзя параллелить; реальный `time.Now()` — нарушает SC-003.
- **Consequence**: `ShelfItem` нельзя сравнивать через `==`. `reflect.DeepEqual` считает функции равными только когда обе `nil`, поэтому проверка «состояние не изменилось» обнуляет `now` в копиях (R9).

## R7. Представление статуса

- **Decision**: `type Status int` с константами через `iota`: `StatusWantToRead` (нулевое), `StatusReading`, `StatusCompleted`, `StatusDropped`; метод `String()`; приватная проверка «допустимое значение» для `ErrInvalidStatus`.
- **Rationale**: нулевое значение получает смысл «хочу прочитать». `String()` делает вывод падающих тестов читаемым. Целое число вне диапазона — единственный способ получить недопустимый статус, его легко проверить.
- **Naming**: имя `ReadingStatus` занято справочником `DESIGN.md` §4.8, поэтому у перечисления имя `Status`.

## R8. Ошибки

- **Decision**: сигнальные ошибки через `errors.New`, проверка через `errors.Is`. Полный список — в [contracts/domain-api.md](./contracts/domain-api.md) (14 штук).
- **Rationale**: FR-021 требует однозначно распознаваемых причин, имя `ErrInvalidRating` задано пользователем.
- **Alternatives considered**: тип ошибки с кодом — избыточно.

## R9. Атомарность и поля-указатели (FR-020)

- **Decision**: каждый метод сначала выполняет все проверки, затем меняет поля. Необязательные поля — указатели (`*time.Time`, `*int`, `*int64`). При изменении методы присваивают указателю новое значение (`l.Pages = &page`) и никогда не пишут через существующий указатель.
- **Rationale**: «проверь, потом меняй» гарантирует неизменность при ошибке. Замена указателя не портит снимок, который тест сделал копией структуры: копия делит указатели с оригиналом.
- **Test technique**: перед вызовом тест копирует `*log` и `*item`, после ошибки сравнивает копии с текущим состоянием через `reflect.DeepEqual`, предварительно обнулив `now`.

## R10. Сравнение времени

- **Decision**: `d.After(now)` — «в будущем», `d.Before(start)` — «раньше старта», `d.After(finish)` — «старт позже окончания». Без усечения до дней.
- **Rationale**: спецификация сравнивает моменты. Равенство с «сейчас» и с другой датой допустимо.

## R11. Табличные тесты и порядок коммитов

- **Decision**: на каждый метод — функция `Test<Сущность>_<Метод>` с таблицей и `t.Run(tc.name, …)`, в каждом подтесте `t.Parallel()`. Тесты по файлам: `shelf_test.go`, `reading_log_test.go`, `review_test.go`.
- **Commit sequence** (принцип II):
  1. `feat: add domain entities and method stubs`: структуры, `Status`, ошибки, заглушки методов, которые ничего не делают и возвращают `nil`;
  2. пары `test:` → `feat:` для каждого метода по порядку: `ShelfItem.ChangeStatus`, `ShelfItem.SetStartDate`, `ShelfItem.SetFinishDate`, `ReadingLog.UpdateProgress`, `ReadingLog.UpdateAudioProgress`, `Review.SetRating`.
- **Rationale**: заглушки позволяют фазе Red падать на проверках, а не на компиляции. `ShelfItem` идёт первым, потому что `ReadingLog` опирается на его состояние.
