# Дизайн-документ: бэкенд учёта чтения

Учебный проект. Этот документ описывает **что должен уметь бэкенд в итоге**, а не как устроен код, какой фреймворк выбран и какая СУБД стоит. Клиент — только HTTP API (web/mobile появятся позже).

---

## 1. Цель продукта

Сервис для **личного учёта чтения**: пользователь ведёт свою полку, отмечает статус и прогресс, пишет оценки и отзывы на книги каталога, фиксирует, когда и сколько читал.

---

## 2. Действующие лица

- **Гость** — смотрит каталог (книги, серии, отзывы и оценки). Регистрируется и входит.
- **Пользователь** — полка, записи о чтении, прогресс, пополнение каталога, свои отзывы.

Роли администратора нет.

---

## 3. Границы версии

- Регистрация и вход (username + пароль)
- Каталог книг: карточки храним у себя. Содержимое при поиске/добавлении берём из [Google Books API](https://developers.google.com/books). Если Google книгу не нашёл — пользователь заводит карточку сам
- Личная полка
- Статус чтения и прогресс
- Записи о чтении (что, когда и сколько прочитал)
- Оценка и отзыв на книгу каталога
- Серии (циклы) книг
- Владение книгой

Позже может появиться модерация книг, которые пользователь завёл вручную (не из Google Books).

---

## 4. Сущности

`*` — nullable.

### 4.1. User

Пользователь приложения.

```
type User struct {
	ID       long
	Username string // уникальный
	Password string // хэш
}
```

### 4.2. Book

Супертип текстовой и аудиокниги. `Type` — дискриминатор подтипа.

```
type Book struct {
	ID        long
	Type      string // text | audio
	ISBN      *string
	Title     string
	Published *Date
	SeriesID  *long // many-to-1 к Series
	SeriesPos *int
}
```

### 4.3. TextBook

Подтип Book, связь is-a.

```
type TextBook struct {
	ID         long // совпадает с Book.ID
	EBook      bool
	TotalPages int
}
```

### 4.4. AudioBook

Подтип Book, связь is-a.

```
type AudioBook struct {
	ID       long // совпадает с Book.ID
	Narrator *string
	Duration long // секунды
}
```

### 4.5. Author

Автор книги.

```
type Author struct {
	ID   long
	Name string
}
```

### 4.6. BookAuthor

many-to-many между Book и Author.

```
type BookAuthor struct {
	AuthorID long
	BookID   long
}
```

### 4.7. Series

Серия книг. 1-to-many к Book.

```
type Series struct {
	ID   long
	Name string // уникально без учёта регистра
}
```

### 4.8. ReadingStatus

Статус записи на полке. 1-to-many к ShelfItem. Стартовый набор: хочу прочитать, читаю, прочитал.

```
type ReadingStatus struct {
	ID   long
	Name string
}
```

### 4.9. ShelfItem

Книга на полке пользователя. Одна пара User и Book — одна запись.

```
type ShelfItem struct {
	ID       long
	UserID   long // many-to-1 к User
	BookID   long // many-to-1 к Book
	StatusID long // many-to-1 к ReadingStatus
}
```

### 4.10. ReadingLog

Сколько прочитано за один подход. Не зависит от ShelfItem. Удаление ShelfItem эти записи не удаляет.

```
type ReadingLog struct {
	ID      long
	UserID  long // many-to-1 к User
	BookID  long // many-to-1 к Book
	Date    Date
	Pages   *int
	Seconds *long // секунды
	Comment *string
}
```

### 4.11. Review

Отзыв на книгу. Один на пару User и Book. С ShelfItem не связан.

```
type Review struct {
	ID     long
	BookID long // many-to-1 к Book
	UserID long // many-to-1 к User
	Rating int  // от 1 до 5
	Text   string
}
```

### 4.12. AcquisitionType

Тип получения книги. 1-to-many к BookOwnership. Стартовый набор: подарок, покупка, библиотечная аренда, другое.

```
type AcquisitionType struct {
	ID   long
	Name string
}
```

### 4.13. Currency

Валюта цены покупки. 1-to-many к BookOwnership.

```
type Currency struct {
	ID   long
	Name string
}
```

### 4.14. BookOwnership

Владение книгой пользователем.

```
type BookOwnership struct {
	ID                long
	UserID            long  // many-to-1 к User
	BookID            long  // many-to-1 к Book
	Acquired          Date
	AcquisitionTypeID long  // many-to-1 к AcquisitionType
	PriceCents        *long // копейки или центы, для покупки
	CurrencyID        *long // many-to-1 к Currency, для покупки
	ReturnDate        *Date // для библиотечной аренды
}
```

## 5. Сценарии

### 5.1. Регистрация и вход

1. Гость задаёт username и пароль.
2. Если username занят — регистрация не проходит.
3. После входа запросы к полке, записям о чтении, созданию и правке карточек и своим отзывам идут от имени этого пользователя.
4. Без входа можно: регистрация, вход, чтение каталога, серий и отзывов.

### 5.2. Найти или завести книгу в каталоге

1. Гость или пользователь ищет книгу у нас (в том числе по ISBN, если он известен).
2. Если карточки нет — **пользователь** может запросить Google Books. Нашли — создаём нашу карточку из ответа.
3. Google ничего не вернул — пользователь заполняет поля сам. ISBN можно не указывать. Если ISBN указан и такая книга уже есть — новую с тем же ISBN не создаём.

Править карточку может любой зарегистрированный пользователь.

### 5.3. Полка

- Добавить карточку на свою полку, если её там ещё нет. При добавлении пользователь **выбирает статус**.
- Сменить статус.
- Удалить запись на полке. Записи о чтении этой книги остаются.
- Список своей полки, фильтр по статусу.

### 5.4. Записи о чтении

- Добавить запись (запись на полке не обязательна).
- Изменить или удалить свою запись.
- Получить свои записи за период (от даты до даты), в том числе по книгам, для которых записи на полке уже нет.
- Процент считает бэкенд по этим записям.

### 5.5. Отзывы

- Поставить оценку и текст на карточку, если ещё не ставил.
- Изменить свою запись.
- Удалить свою запись.
- Получить отзывы книги.

### 5.6. Серии

- Получить серию: название, сколько книг (считается), список книг с позициями.
- Отдельно «пустую» серию не создаём: серия появляется, когда на неё ссылается книга.

---

## 6. Правила доступа

Каталог, серии, отзывы:

- читать может гость и пользователь
- создать карточку книги — только пользователь (из Google Books или вручную, если Google не нашёл)
- править карточку — любой зарегистрированный пользователь
- писать и менять отзыв — только автор этого отзыва

Полка и статус:

- читает и меняет владелец

Записи о чтении:

- читает и меняет владелец

Владение:

- читает и меняет владелец

Пользователь:

- владелец видит свои данные, хэш пароля наружу не отдаём
- смену пароля и username в этой версии не делаем

---

## 7. Инварианты

1. Невозможно добавить книгу с уже существующим ISBN в каталоге.
2. Пользователь не может добавить одну книгу на полку дважды.
3. Записи о чтении ссылаются на пользователя и карточку. Удаление записи на полке эти записи не удаляет.
4. Один отзыв на пару «пользователь + карточка».
5. Оценка только 1, 2, 3, 4 или 5.

---

## 8. Что сознательно не зафиксировано

- СУБД
- Формат URL и стиль HTTP API
- Архитектура пакетов Go
- Сеть магазинов, в которой куплена книга
- Выбор библиотеки (нужен API карт)
