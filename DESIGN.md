# Дизайн-документ: бэкенд учёта чтения

Учебный проект. Этот документ описывает **что должен уметь бэкенд в итоге**, а не как устроен код, какой фреймворк выбран и какая СУБД стоит. Клиент — только HTTP API (web/mobile появятся позже).

---

## 1. Цель продукта

Сервис для **личного учёта чтения**: пользователь ведёт свою полку, отмечает статус и прогресс, пишет оценки и отзывы на книги общего каталога, фиксирует сессии чтения в календаре.

Это не социальная сеть: нет друзей, ленты, клубов и публичного профиля «для других людей как продукт». Отзывы живут на книге каталога (их видит любой, кто смотрит карточку книги), но нет механик подписок и рекомендаций «от друзей».

---

## 2. Действующие лица

| Роль | Что делает |
| --- | --- |
| Гость | Смотрит каталог (книги, серии, отзывы и оценки). Регистрируется и входит |
| Пользователь | Полка, календарь, прогресс, пополнение каталога, свои отзывы |

Роли администратора нет.

---

## 3. Границы версии

### Входит

- Регистрация и вход (username + пароль), доступ по JWT
- Общий каталог книг
- Пополнение каталога из внешнего источника по ISBN; ручное добавление — только если книги нет во внешнем источнике
- Личная полка
- Статус чтения и прогресс
- Календарь сессий чтения
- Оценка и отзыв на книгу каталога
- Серии (циклы) книг

### Не входит

- Друзья, подписки, лента, книжные клубы
- Заметки и цитаты как отдельная сущность (у записи календаря может быть короткий комментарий — это не дневник цитат)
- Статистика, streak, годовые отчёты, графики
- Админка и модерация каталога
- Правка уже созданных записей каталога пользователями
- Выбор конкретного внешнего API (фиксируется отдельным решением на этапе реализации)
- Стиль API (REST/RPC/gRPC), слои кода, выбор БД — **не часть этого документа**

## 4. Сущности и поля

### 4.1. Пользователь

- Уникальный `username`
- Пароль (хранится только в виде хэша)
- Идентификатор

Email, восстановление пароля, OAuth — нет.

### 4.2. Серия

- Название серии
- Книги, которые на неё ссылаются

**Количество книг в серии не хранится:** его всегда считают как число книг каталога, у которых указана эта серия.

Серия у книги **не обязательна**.

### 4.3. Книга каталога

Идентичность: **одна запись = один ISBN**. ISBN обязателен и уникален. Книгу без ISBN в каталог не кладём.

Поля:

- ISBN
- Название
- Авторы (список, минимум один)
- Год издания, если источник его отдал
- Серия (необязательно) и позиция в серии (обязательна, если серия указана)
- Тип: **бумажная** или **аудиокнига**
- Если тип «бумажная»: признак **электронная / не электронная**
- Если тип «аудиокнига»: **рассказчик** (обязателен)

Прогрессные величины «всего»:

- Для бумажной и электронной: **число страниц**
- Для аудиокниги: **длительность в секундах**

### 4.4. Запись на полке

Принадлежит одному пользователю и ссылается на **одну книгу каталога**.

На полке нельзя дважды добавить одну и ту же запись каталога. Бумажную и аудиоверсию одного произведения можно держать одновременно, **если у них разные ISBN** (это разные записи каталога).

Проценты в БД не хранятся.

Поля:

- Пользователь
- Книга каталога
- Статус: `хочу прочитать` | `читаю` | `прочитал`
- Текущий прогресс:
  - страницы — для бумажной / электронной
  - секунды — для аудиокниги

Статус и прогресс **независимы**: сервер не заставляет «прочитал» быть 100% и не обнуляет прогресс при «хочу прочитать».

Процент считается в коде:

- текст: `текущая_страница / всего_страниц`
- аудио: `текущие_секунды / всего_секунд`

Если «всего» неизвестно или равно 0, процент не считается (не подставляем 0 как «правду»).

### 4.5. Запись календаря (сессия)

Журнал, не таймер старт/стоп.

Каждая запись:

- Пользователь (календарь личный)
- Дата
- Книга **каталога** (не строка полки)
- Сколько прочитано за подход: страницы **или** секунды (по типу книги)
- Необязательный короткий комментарий к подходу

В один день разрешено **несколько** записей (разные книги или несколько подходов).

Новую запись можно создать, только если эта книга **сейчас** есть на полке пользователя. В самой записи полка не хранится: после снятия книги с полки сессии **остаются** и по-прежнему показывают, что человек эту книгу читал. Пока книги нет на полке, новые сессии по ней добавить нельзя (пока снова не положат на полку). Существующие записи календаря можно смотреть, менять и удалять независимо от полки.

Календарь не двигает статус сам по себе. Нужно отдельно решить при реализации (не в этом документе), обновляет ли добавление сессии текущий прогресс на полке или прогресс меняют только явным запросом. Пока продуктовое правило такое: **прогресс на полке и календарь — разные факты**; пользователь может вести оба.

### 4.6. Оценка и отзыв

Живут на **книге каталога**, не на записи полки.

- Оценка: целое **1–5**
- Текст отзыва
- Автор — пользователь

Правило: **не больше одной пары оценка+отзыв** на пару (пользователь, книга каталога). Можно изменить и удалить свою запись. Чужие нельзя.

Карточку книги в каталоге, отзывы и оценки может читать **гость**. Писать и менять отзыв — только автор, после входа. Агрегат «средняя оценка» — производное от существующих оценок (считать в коде или запросом к БД — деталь реализации).

## 5. Сценарии

### 5.1. Регистрация и вход

1. Гость задаёт `username` и пароль.
2. `username` занят — регистрация отклоняется.
3. Успешный вход выдаёт **JWT access-токен**. Refresh-токенов нет.
4. Запросы к полке, календарю, созданию книг в каталоге и своим отзывам — с этим токеном. Без токена доступны: регистрация, вход, **чтение** каталога, серий и отзывов.

### 5.2. Найти или завести книгу в каталоге

1. Гость или пользователь ищет уже существующую книгу (в том числе по ISBN).
2. Если книги в каталоге нет, **только пользователь** может завести её: бэкенд запрашивает **внешний провайдер** (конкретный API не выбран) и при успехе создаёт запись.
3. Если внешнего результата нет — пользователь **сам** передаёт поля из §4.3 (включая ISBN). Повтор того же ISBN запрещён.

Пользователь не редактирует чужие и свои уже созданные карточки каталога в этой версии.

### 5.3. Полка

- Добавить книгу каталога на свою полку (если её там ещё нет), стартовый статус — `хочу прочитать`, прогресс — 0 страниц или 0 секунд.
- Сменить статус.
- Записать текущий прогресс (страница или секунды).
- Убрать книгу с полки. Записи календаря по этой книге **не удаляются**.
- Список своей полки, фильтр по статусу.

Чужая полка недоступна.

### 5.4. Календарь

- Добавить свою запись (книга должна быть на полке в этот момент).
- Изменить / удалить свою запись (полка не требуется).
- Получить записи за период (от даты до даты), в том числе по книгам, которых уже нет на полке.

Чужой календарь недоступен.

### 5.5. Отзывы

- Поставить оценку и текст на книгу каталога (если ещё не ставил).
- Изменить свою запись.
- Удалить свою запись.
- Получить отзывы книги и свою запись, если есть.

### 5.6. Серии

- Получить серию: название, вычисленное число книг, список книг каталога с позициями.
- Создавать серию отдельно «в пустоту» не нужно: серия появляется, когда книга в каталоге на неё ссылается (импорт или ручное создание). Поведение при двух одинаковых названиях серий: **название серии уникально** (чтобы не плодить дубли «Ведьмак» и «ведьмак» — сравнение без учёта регистра).

## 6. Правила доступа

| Данные | Кто читает | Кто меняет |
| --- | --- | --- |
| Каталог, серии, отзывы | Гость и пользователь | Создать книгу: только пользователь (импорт или ручной ввод при промахе внешнего API). Отзыв: только автор своей записи |
| Полка, прогресс, статус | Только владелец | Только владелец |
| Календарь | Только владелец | Только владелец |
| Пользователь (пароль, username) | Только владелец (без выдачи хэша пароля) | Смена пароля / username в этой версии не требуется |

## 7. Инварианты (чтобы не разъехалось при реализации)

1. ISBN в каталоге уникален и обязателен.
2. Тип книги фиксирует форму прогресса: страницы **или** секунды, не оба сразу.
3. Рассказчик есть только у аудио; признак «электронная» — только у бумажной.
4. Позиция в серии задаётся только вместе с серией.
5. На полке уникальна пара (пользователь, книга каталога).
6. Сессия календаря ссылается на пользователя и книгу каталога. Снятие книги с полки сессии не трогает.
7. Новый сеанс в календарь — только если книга в этот момент на полке автора сессии.
8. Один отзыв на (пользователь, книга каталога).
9. Оценка только 1, 2, 3, 4 или 5.

## 8. Что сознательно не зафиксировано

Это не пробелы продукта, а отложенные технические решения:

- Конкретный внешний API каталога
- СУБД
- Формат URL и стиль HTTP API
- Архитектура пакетов Go
- Нужно ли при добавлении сессии автоматически увеличивать прогресс на полке (сейчас это **два независимых факта**)

## 9. Откуда взяты решения

Решения — из ответов на вопросы по продукту. Ниже только внешние якоря, чтобы объяснить ментору формулировки, а не «выбор стека».

- ISBN как идентификатор издания: стандарт [ISO 2108](https://www.iso.org/standard/65483.html) / практика каталогов (одно издание — один ISBN).
- JWT как access-токен без refresh: модель из [RFC 7519](https://datatracker.ietf.org/doc/html/rfc7519) и учебный сценарий «логин вернул токен, им ходим в API». Refresh усложняет учебный контур и в эту версию не входит.
- Процент как производное, а не колонка: меньше расхождений, когда «всего страниц» уточнили; процент всегда можно пересчитать.
- Каталог общий + полка личная: обычное разделение «карточка издания» / «экземпляр у пользователя», чтобы отзывы и ISBN не копировались на каждого читателя.
